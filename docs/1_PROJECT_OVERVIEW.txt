1. ARCHITECTURE SUMMARY
--------------------------------------------------------------------------------

The system is a full-stack Enterprise HRMS built on a two-tier architecture:

  Frontend   : React 18 + TypeScript + Vite  (port 3000 in development)
  Backend    : FastAPI + Python               (port 8004)
  Database   : MySQL 8.0                     (database name: hrms)
  Production : Nginx reverse proxy serving the React SPA and proxying
               /api/ and /auth/ to the FastAPI backend container

DATABASE POLICY (enforced):
  The project uses ONLY MySQL (mysql-connector-python 9.7.0).
  There is NO PostgreSQL, NO SQLite, NO MongoDB, NO MariaDB, NO Prisma,
  NO SQLAlchemy, NO psycopg2, NO asyncpg, NO mongoose anywhere in the project.

  The only secondary connection is pyodbc to a SQL Server instance.
  That connection is READ-ONLY and is used exclusively to pull biometric
  punch records from the TimeWatch/IDMS hardware device.
  It is NOT a second HRMS database.

5. AUTHENTICATION
--------------------------------------------------------------------------------

Login Flow
  Step 1: POST /api/auth/login
          Validates username + password
          Supports bcrypt hashed passwords (new accounts, $2b$ prefix)
          Supports legacy plain-text passwords (admin001, hr001, acc001)
          Returns: { success, requires_otp: true, otp: "6-digit string" }

  Step 2: POST /api/auth/verify-otp
          Accepts any 6-digit OTP (server-side: accepts any valid 6-digit code)
          Returns: { success, token, user: { user_id, username, email,
                    full_name, role, profile_completed } }

  Step 3: Frontend stores user object in localStorage key "hrms_user"
          via Zustand persist middleware

  Step 4: All API calls include Authorization header with token value
          Axios interceptor reads from localStorage("hrms_user")
          401 responses redirect to /login

Token Format: "token_{user_id}"  (simple string, not JWT)

Role Permissions
  admin       Full access: all HR, admin, employee, and accountant functions
  hr          HR management: employees, leave approval, document generation,
              attendance management, announcements
  accountant  Finance only: payroll, salary slip generation, expenses,
              reimbursements, financial reports
  employee    Self-service: own attendance, own leave, own documents,
              own payslips, own profile, own expenses


6. MODULES
--------------------------------------------------------------------------------

Authentication Module
  Employee self-registration with work mode commitment (WFO/WFH)
  Biometric enroll_id registered at signup for WFO employees
  OTP-based two-step login
  Role-based dashboard redirect after login

Employee Module
  Employee creation by HR/Admin
  Employee profile completion (KYC, bank details, uploaded documents)
  Employee directory with search and department grouping
  Employee status management (active/inactive)

Attendance Module
  WFO employees: biometric machine integration
    - Biometric enroll_id registered at onboarding
    - TimeWatch/IDMS SQL Server polled every 3 seconds
    - Punch data synced to attendance table
    - Live attendance feed for HR
  WFH employees: selfie + GPS
    - Selfie captured in browser, AES-256-GCM encrypted, stored on disk
    - GPS coordinates validated against registered home location
    - Configurable geo-fence radius (default 500m)
    - Home location registration and HR-approved change request workflow
  Work mode committed ONCE at signup (default_work_mode column)
  Daily work mode row auto-created when employee visits attendance page
  Late arrival tracking:
    - beyond_grace flag set if check_in > 09:45
    - Deduction triggered after 3 late-beyond-grace days in a month
    - Deduction = half-day salary per set of 3 late days

Leave Module
  Employee applies for leave (full day, first half, second half)
  HR approves or rejects with comments
  On approval: paid days deducted from leave_balance first,
               remaining days marked as unpaid
  Payroll row refreshed immediately on approval
  Leave balance display with casual, sick, earned breakdown
  Leave calendar view
  Notification sent to all HR/Admin on new leave request

Document Module
  Employee submits document request (offer letter, experience letter,
  relieving letter, appointment letter, salary slip)
  HR reviews all requests
  For non-salary-slip: HR approves and generates PDF using official template
  For salary slip: HR approves and forwards to Accountant
  Accountant generates salary slip PDF (HR cannot generate salary slips)
  All documents use official Seawind Solution DOCX templates from
  backend/templates/templates/
  Generated PDFs stored in generated_docs/
  Documents visible only to the requesting employee

Salary / Payroll Module
  HR manages salary structures via /api/hr/salary (CTC breakdown)
  Canonical payroll formula (payroll_engine.py):
    net = gross - PT(200) - leave_deduction
    leave_deduction = (gross / total_days_in_month) * unpaid_days
  Accountant views and processes payroll via /api/accountant/payroll
  Payslip HTML preview via /api/payslip/
  Salary slip PDF generation via official template (Accountant only)

Task Management Module
  Kanban board with To Do, In Progress, Done columns
  Task assignment by HR/Admin to employees
  Task performance metrics: completion rate, on-time rate, weighted score

Analytics Module
  Employee count and department distribution
  Attendance rate and leave statistics
  Role distribution, active/inactive user counts

Announcements Module
  HR/Admin posts announcements
  Fan-out: one notification row created per active user

Reports Module
  Employee summary, department, payroll, attendance, leave, performance
