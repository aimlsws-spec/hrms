1. PREREQUISITES
--------------------------------------------------------------------------------

Software Requirements

  Python          3.10 or higher (3.11 recommended)
  Node.js         18.x or higher (20.x LTS recommended)
  npm             9.x or higher
  MySQL           8.0.x
  Microsoft Word  Required on Windows for docx2pdf PDF conversion
                  (Word must be installed and licensed on the server)
  ODBC Driver     "ODBC Driver 17 for SQL Server" (for biometric integration)
                  Only required if biometric hardware is connected

Operating System
  Development : Windows 10/11 (current deployment environment)
  Production  : Linux (Ubuntu 22.04 LTS recommended) or Windows Server 2019+
  Note        : docx2pdf uses Microsoft Word COM automation.
                On Linux, LibreOffice must be installed as a substitute,
                or the salary slip generator must use the reportlab fallback.

Hardware Minimum (Production)
  CPU     : 2 cores
  RAM     : 4 GB
  Disk    : 20 GB (plus storage for generated_docs and wfh_selfies)
  Network : Static IP or domain name for Nginx

3. DATABASE SETUP
--------------------------------------------------------------------------------

Step 1: Create the MySQL database

  mysql -u root -p
  CREATE DATABASE hrms CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
  CREATE USER 'hrms_user'@'localhost' IDENTIFIED BY '<strong_password>';
  GRANT ALL PRIVILEGES ON hrms.* TO 'hrms_user'@'localhost';
  FLUSH PRIVILEGES;
  EXIT;

Step 2: Import the full schema and seed data

  mysql -u root -p hrms < backend/sql/sql/hrms_dump.sql

  This creates all tables, indexes, triggers, and inserts seed data including:
    - Default admin, HR, and accountant user accounts
    - Tax slab configuration
    - Salary template
    - Accountant settings
    - WFH system configuration

Step 3: Verify the import

  mysql -u root -p hrms -e "SHOW TABLES;" | wc -l
  Expected: approximately 40+ tables

Default Credentials (change immediately in production)

  Role        Username    Password
  Admin       admin       admin123
  HR          hr          hr123
  Accountant  accountant  acc123

  IMPORTANT: These are plain-text passwords in the database.
  Change them immediately after first login or run:
    UPDATE users SET password = '<bcrypt_hash>' WHERE username = 'admin';
  Use Python to generate bcrypt hash:
    python -c "import bcrypt; print(bcrypt.hashpw(b'NewPassword', bcrypt.gensalt()).decode())"


4. MIGRATION STEPS
--------------------------------------------------------------------------------

The application performs automatic idempotent migrations on startup via:
  _migrate_schema()         in app.py
  _migrate_attendance_cols() in attendance_api.py
  _ensure_leave_tables()    in app.py
  _ensure_announcement_tables() in app.py

These functions use ALTER TABLE ... ADD COLUMN IF NOT EXISTS patterns and
CREATE TABLE IF NOT EXISTS, so they are safe to run on an existing database.

For a fresh install, the hrms_dump.sql already contains the complete schema.

For upgrading an existing installation, the individual SQL scripts in
backend/sql/sql/ can be applied in order:
  1. hrms_dump.sql              (base schema - use only for fresh install)
  2. attendance_tables.sql
  3. wfh_selfie_tables.sql
  4. wfh_geo_tables.sql
  5. accountant_schema.sql
  6. payroll_tables.sql
  7. leave_ledger.sql
  8. task_manager_schema.sql
  9. performance_tables.sql
  10. admin_features_schema.sql
  11. audit_tables.sql
  12. additional_tables.sql
  13. critical_features.sql
  14. fix_salary_and_accountant.sql

5. BACKEND BUILD AND RUN
--------------------------------------------------------------------------------

Step 1: Navigate to the project root

  cd "d:\hr management\hrms_agent"

Step 2: Create and activate a Python virtual environment

  Windows:
    python -m venv venv
    venv\Scripts\activate

  Linux:
    python3 -m venv venv
    source venv/bin/activate

Step 3: Install Python dependencies

  pip install -r backend/requirements.txt

  Note: docx2pdf is not in requirements.txt but is used by salary_slip_generator.py
  and the letter generators. Install separately if needed:
    pip install docx2pdf

Step 4: Verify the .env file is in the project root

  The backend reads .env from the working directory via python-dotenv.
  Always run uvicorn from the project root (hrms_agent/).

Step 5: Run the backend (development)

  uvicorn backend.app:app --host 0.0.0.0 --port 8004 --reload

Step 6: Run the backend (production)

  uvicorn backend.app:app --host 0.0.0.0 --port 8004 --workers 1 --no-access-log

  Note: Use workers=1 because APScheduler and biometric sync use in-process
  state. Multiple workers would create duplicate scheduler instances.

Step 7: Verify backend is running

  curl http://localhost:8004/health
  Expected response: "ok"

  curl http://localhost:8004/health/db
  Expected response: {"status": "success", "db": "connected"}


6. FRONTEND BUILD AND RUN
--------------------------------------------------------------------------------

Step 1: Navigate to the frontend directory

  cd "d:\hr management\hrms_agent\frontend"

Step 2: Install Node.js dependencies

  npm install

Step 3: Run the frontend (development)

  Frontend available at: http://localhost:3000
  API calls proxied to: http://127.0.0.1:8004

Step 4: Build the frontend (production)

  npm run build
  Output directory: frontend/dist/

Step 5: Preview the production build locally

  npm run preview


7. PRODUCTION DEPLOYMENT STEPS
--------------------------------------------------------------------------------

Option A: Direct deployment on Linux server

  1. Install system dependencies
     sudo apt update
     sudo apt install -y python3.11 python3.11-venv python3-pip nodejs npm
     sudo apt install -y mysql-server nginx
     sudo apt install -y libreoffice  (for PDF generation on Linux)
     sudo apt install -y unixodbc unixodbc-dev  (for biometric integration)

  2. Clone or copy the project to /opt/hrms_agent/

  3. Set up MySQL (see Database Setup section above)

  4. Create .env file at /opt/hrms_agent/.env

  5. Set up Python virtual environment and install dependencies
     cd /opt/hrms_agent
     python3.11 -m venv venv
     source venv/bin/activate
     pip install -r backend/requirements.txt

  6. Build the React frontend
     cd /opt/hrms_agent/frontend
     npm install
     npm run build

  7. Configure Nginx
     Copy frontend/nginx.conf to /etc/nginx/sites-available/hrms
     Update server_name with your domain or IP
     Update the root path to /opt/hrms_agent/frontend/dist
     Enable the site:
       sudo ln -s /etc/nginx/sites-available/hrms /etc/nginx/sites-enabled/
       sudo nginx -t
       sudo systemctl reload nginx

  8. Create systemd service for the backend
     Create /etc/systemd/system/hrms-backend.service:

       [Unit]
       Description=HRMS FastAPI Backend
       After=network.target mysql.service

       [Service]
       User=www-data
       WorkingDirectory=/opt/hrms_agent
       EnvironmentFile=/opt/hrms_agent/.env
       ExecStart=/opt/hrms_agent/venv/bin/uvicorn backend.app:app \
                 --host 127.0.0.1 --port 8004 --workers 1
       Restart=always
       RestartSec=5

       [Install]
       WantedBy=multi-user.target

     Enable and start:
       sudo systemctl daemon-reload
       sudo systemctl enable hrms-backend
       sudo systemctl start hrms-backend

  9. Create required directories with correct permissions
     mkdir -p /opt/hrms_agent/generated_docs
     mkdir -p /opt/hrms_agent/wfh_selfies
     mkdir -p /opt/hrms_agent/employee_data
     chown -R www-data:www-data /opt/hrms_agent/generated_docs
     chown -R www-data:www-data /opt/hrms_agent/wfh_selfies
     chown -R www-data:www-data /opt/hrms_agent/employee_data

  10. Verify deployment
      curl http://localhost:8004/health
      curl http://localhost:8004/health/db
      Open browser: http://your-domain/login

Option B: Docker deployment

  The project does not currently include a Dockerfile.
  To containerize:

  Backend Dockerfile (create at backend/Dockerfile):
    FROM python:3.11-slim
    WORKDIR /app
    COPY requirements.txt .
    RUN pip install -r requirements.txt
    COPY . .
    CMD ["uvicorn", "backend.app:app", "--host", "0.0.0.0", "--port", "8004"]

  Frontend Dockerfile (create at frontend/Dockerfile):
    FROM node:20-alpine AS build
    WORKDIR /app
    COPY package*.json .
    RUN npm install
    COPY . .
    RUN npm run build

    FROM nginx:alpine
    COPY --from=build /app/dist /usr/share/nginx/html
    COPY nginx.conf /etc/nginx/conf.d/default.conf

  Note: docx2pdf requires Microsoft Word or LibreOffice.
  In a Docker container, install LibreOffice and use a LibreOffice-based
  PDF conversion wrapper instead of docx2pdf.


8. NGINX CONFIGURATION (Production)
--------------------------------------------------------------------------------

The nginx.conf in frontend/ is the production configuration.
Key settings:

  server {
    listen 80;
    server_name your-domain.com;
    root /path/to/frontend/dist;
    index index.html;

    # Proxy API calls to FastAPI backend
    location /api/ {
      proxy_pass http://backend:8004;
      proxy_read_timeout 180s;  # Required for docx2pdf (Word startup ~60s)
    }

    location /auth/ {
      proxy_pass http://backend:8004;
    }

    # SPA fallback
    location / {
      try_files $uri $uri/ /index.html;
    }
  }

The 180-second proxy timeout is required because docx2pdf (Microsoft Word)
can take 60+ seconds on first call when Word starts up.


9. CORS CONFIGURATION
--------------------------------------------------------------------------------

CORS is configured in app.py. Allowed origins:

  http://localhost:5173
  http://127.0.0.1:5173
  http://localhost:8004
  http://127.0.0.1:8004
  http://localhost:8003
  http://127.0.0.1:8003
  http://localhost:3000
  http://127.0.0.1:3000
  http://localhost:8002
  http://127.0.0.1:8002

For production, add your production domain to the allow_origins list in app.py:
  "https://your-domain.com"

Note: allow_origins=["*"] is NOT used because allow_credentials=True is set.
Browsers reject wildcard origins with credentials.


10. REQUIRED DIRECTORIES
--------------------------------------------------------------------------------

These directories must exist and be writable by the backend process:

  generated_docs/     PDF output for salary slips and letters
  wfh_selfies/        Encrypted WFH selfie files
  employee_data/      Employee uploaded documents (KYC, certificates)
  templates/          Jinja2 HTML templates (legacy, still referenced)
  backend/templates/templates/  Official DOCX document templates

The backend creates wfh_selfies/ automatically on startup via
selfie_storage.ensure_storage_dir().

generated_docs/ and employee_data/ must be created manually before first run.


11. ROLLBACK PROCEDURE
--------------------------------------------------------------------------------

Step 1: Stop the backend service
  sudo systemctl stop hrms-backend  (Linux)
  or kill the uvicorn process (Windows)

Step 2: Restore the previous code version
  git checkout <previous_tag_or_commit>
  or restore from backup archive

Step 3: Restore the database if schema changes were made
  mysql -u root -p hrms < backup_before_deployment.sql

Step 4: Restart the backend
  sudo systemctl start hrms-backend

Step 5: Rebuild and redeploy the frontend if needed
  cd frontend && npm run build
  Copy dist/ to Nginx root

Database Backup (run before every deployment):
  mysqldump -u root -p hrms > backup_$(date +%Y%m%d_%H%M%S).sql


12. TROUBLESHOOTING
--------------------------------------------------------------------------------

Backend fails to start
  Check: python -c "from backend.app import app" for import errors
  Check: .env file exists in the working directory
  Check: MySQL is running and credentials are correct
  Check: All required packages are installed (pip list)

Database connection refused
  Check: MySQL service is running (sudo systemctl status mysql)
  Check: DB_HOST, DB_PORT, DB_USER, DB_PASSWORD, DB_NAME in .env
  Check: MySQL user has GRANT ALL on hrms database
  Test: mysql -u root -p -e "SELECT 1"

PDF generation fails
  Windows: Ensure Microsoft Word is installed and licensed
  Linux: Install LibreOffice (sudo apt install libreoffice)
  Check: generated_docs/ directory exists and is writable
  Check: DOCX templates exist in backend/templates/templates/

WFH selfie upload fails
  Check: wfh_selfies/ directory exists and is writable
  Check: SELFIE_ENCRYPTION_KEY is set in .env (64 hex chars)
  Check: Pillow is installed (pip show pillow)

Biometric sync not working
  Check: IDMS SQL Server is accessible from the backend server
  Check: ODBC Driver 17 for SQL Server is installed
  Check: IDMS_SERVER, IDMS_DATABASE, IDMS_USER, IDMS_PASSWORD in .env
  Check: biometric_employee_map table has enroll_id entries

Frontend shows blank page
  Check: npm run build completed without errors
  Check: Nginx root points to frontend/dist/
  Check: Nginx SPA fallback (try_files) is configured
  Check: Browser console for JavaScript errors

API calls return 404
  Check: Backend is running on port 8004
  Check: Nginx proxy_pass points to correct backend URL
  Check: Vite proxy in vite.config.ts (development only)

API calls return 500
  Check: backend logs (uvicorn output)
  Check: Database tables exist (run backend/sql/sql/hrms_dump.sql if missing)
  Check: _migrate_schema() ran successfully on startup
